02

The solution: deterministic first

Every answer comes from the customer's own data. Models only help understand the question.

An action reads the session customer's data and returns facts. A template phrases those facts in the customer's language, and can show nothing else. A small embedding model and a small local LLM help understand the message; neither can write the answer.

03

How the data led there

The brief

A secure web page where a bank's customers log in and chat with an agent. It had to:

  • meet industry-standard security and log every event;
  • close the session after 5 minutes idle;
  • support Spanish and Portuguese (a hackathon requirement);
  • answer in under a second (since revised to 4 seconds);
  • route by difficulty to cut cost, and hand a case to a person when needed.

The data we were given

Ten datasets, three years of daily files (June 2023 to June 2026), 213k satisfaction surveys. We tested four hypotheses before designing anything.

Why there is no machine learning model

Nothing in the data predicts anything.

Across every analysis, the variables a model would learn from move independently of the outcomes. A model trained on this data would fit noise: it would look accurate on these files and fail on real customers.

The data also looks generated: days_past_due takes only 7 values, delinquency is a flat 15% in every segment, surveys hold 13 distinct comments, and a complaint's product never belongs to the complainant.

No large opportunity needed a predictive model. The one machine learning technique the solution uses is vector similarity, to match a customer's message with known phrasings.

The decision

Automate the recurring questions.

Customers ask for balances and keep asking how their open complaints are going. Both can be answered from data the bank holds for that customer, with no person involved.

≈92,000 jobs a year handled by people, 11,321 of them call-center complaints

Automating the repetitive ones frees people for the hard cases: an unrecognised charge, a lost card, a loan.

Built in three phases, measured at every step

krtr back ia evaluate · evaluate-llm

Phase 1 · deterministic core

Actions, slot filling, ES and PT templates, clarification, the repetition rule. No model at all, fully testable offline. Then language detection per conversation, latency per step, and encrypted chat messages.

Phase 2 · vector similarity

MiniLM, run locally through ONNX at ≈2.5 ms. Thresholds measured per language with one rule: no wrong match, ever.

The platform, chosen for development time

Two developers, both working full time

Every infrastructure choice was judged by how fast we could change it and test it.

Modal

Google Cloud's free trial requires a payment. Modal's Starter credits run our code without Docker image builds, so changes are tested quickly.

Neon

Serverless Postgres with a free tier and branches for dev and production, easy to use from Modal.

Keycloak

Open-source, standard login (OIDC with PKCE) for the 150,000 accounts, at no cost.

FastAPI

A backend-for-frontend: the browser never sees a token, and session cookies are HttpOnly, Secure and __Host-.

Local models

MiniLM and Qwen run inside the app: no per-token cost, no data leaving, and they run in tests.

Clean code

Vertical slices, every model chosen from a fixed list, SQL in .sql files, events encrypted with AES-256-GCM.

04

Next steps

Agent

More deterministic answers

Open more intents the agent can solve from data, starting with a polite close and filing a complaint with its category, so fewer cases need a person.

Agent

Some independence

Give the agents more room where it is safe, such as phrasing replies or chaining steps, while every fact still comes from a deterministic action.

Agent

Bundles by config

Package each agent (intents, phrases, thresholds, models, prompts) as a versioned configuration, so a version can be deployed, compared and rolled back.

Platform

Cheaper, stable infra

Look for hosting that costs less and is more stable than a monthly credit budget, for the web app, the login service and the models.

Platform

Docker

Containerise the repository, so it runs the same way on every machine and on any provider.

Platform

Microservices

Split the vertical slices (web, security, agent, data) into services that can be deployed and scaled on their own.
